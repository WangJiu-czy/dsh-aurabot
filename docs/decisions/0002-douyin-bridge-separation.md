# ADR-0002: 分离抖音消息桥与浏览器能力

## 状态

Accepted

## 日期

2026-10-30

## 背景

抖音消息 SDK 与 ego-lite 浏览器是两套独立登录和运行通道。此前两者由 `douyin` 模块共同创建，导致消息生命周期、浏览任务和面板路由绑在一起；消息 SDK 实际已通过通用 `imAdapters` 接缝接入共享 hub。

## 决策

新增独立内置模块 `douyin-bridge`，唯一负责 SDK 消息接入、会话 registry 注册、消息状态/登录路由和清理；原 `douyin` 模块只负责 ego-lite 浏览、观看、互动及浏览器设置。消息依旧进入共享 hub，回复沿用现有会话权限与发送流程。原 `/douyin/im/*` 路由地址保持不变以兼容当前面板与本地调用。

## 考虑过的方案

- **继续把两类能力留在一个模块**：依赖更少，但关闭或替换浏览功能会同时影响消息桥，职责仍混杂。
- **另建一套抖音聊天中枢**：会复制 hub 的消息权限、记忆和发送语义，放弃；复用 `imAdapters` 与现有 hub。
- **把ego-lite当作抖音消息传输**：浏览器态和 SDK 登录态独立，混作一个传输会造成身份/回执误判，放弃。

## 结果

两个模块可分别启停，IM 共享 registry 和 hub 不变。已删除浏览器私信收件轮询、独立 system-turn 回复、重复游标状态、旧轮询配置和 `/douyin/dms` 路由；指定对象私信与分享仍使用浏览器执行器。旧配置归一化时会丢弃 `ownerDm` / `dmPollMinutes`。网页与 SDK 双 UID 联动、媒体/原生语音、异步任务回原会话及真实页面回执仍按 T4/T5 验证清单跟进，不以模块拆分宣称完成。
